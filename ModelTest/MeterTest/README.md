# MeterTest 执行测试流程说明

本文档说明 MeterTest 点击“执行测试”后的完整逻辑，以及测试方案、工位、控制 PCB、源控制、日志和数据库之间的关系。

## 0. 代码职责边界

`MeterTest.cs` 现在只承担以下职责：

1. 响应按钮、TreeView、DataGridView 等 UI 事件。
2. 解析当前选中的方案上下文，并按顺序调度测试小项。
3. 把服务返回的工位结果刷新到表格、树节点状态灯和右侧日志。
4. 维护本轮取消令牌、界面结果缓存和自动/手动保存时机。

所有会访问硬件、构造或解析报文、计算测试参数、等待试验时间、判断结果的代码均位于独立服务：

| 服务 | 负责流程 |
| --- | --- |
| `MeterTestRunPreparationService` | 每轮唯一一次资产加载、0x82 台体切换和源 Ini 初始化 |
| `MeterTestCommunicationTestService` | 通信测试、F3/F1 波特率同步、698 地址读取和备用波特率 |
| `MeterTestDeviceSelfCheckService` | 0x86 短路、0x84 断路和 0xCA 温度自检 |
| `MeterTestDailyTimingService` | 日计时启动、倒计时、三轮结果读取和平均误差 |
| `MeterTestStartingErrorService` | 起动试验升源后 A2/A0/0x38、等待、读取和判定 |
| `MeterTestCreepingTestService` | 潜动 0x25 启动、等待、结果读取和脉冲判定 |
| `MeterTestConstantTestService` | 常数试验电量读取、0x37 启停/读取、等待和结果判定 |
| `MeterTestBasicErrorService` | 正向/反向有功基本误差完整点位流程 |
| `MeterTestBluetoothInterfaceService` | 蓝牙波特率、复位、连接、预处理和 698 地址读取 |
| `MeterTestSourceControlService` | XYCtr 开串口、Ini、升降源、标准表采样和达标验证 |
| `MeterTestControlPcbCommandService` | 控制 PCB 分组映射、批量发送、应答收集和协议校验 |
| `MeterTestStationTcpSessionService` | 工位 485 TCP 长连接、缓存清理和完整 698 帧筛选 |

### 0.1 接口日志规范

所有硬件接口日志至少包含以下信息：

1. 接口或命令名称，例如 `XYCtr.AnyUIOutput`、`F3`、`F1`、`0x38+AA`。
2. 目标端点、工位号和控制 PCB 表位地址。
3. 调用参数、超时时间及完整下行 HEX 报文。
4. 接口返回值及完整上行 HEX/原始文本。
5. 超时、取消或异常发生的具体阶段。
6. 协议解析结果、实测值、允许区间和最终结论。

接口日志同时进入全局 `LogMessage`；需要按工位追踪的流程还会写入
`XCKJ_logs/TextLog/yy/MM/dd/TestItem工位N.log`。同一个 `TestItem` 的全部内部步骤写入同一文件。

## 1. 总体流程

点击“执行测试”按钮后，入口是 `MeterTest.StartSelectedTestAsync()`。

执行顺序如下：

1. 判断当前是否已有测试任务正在运行，防止重复启动。
2. 检查左侧 TreeView 是否已经选中方案、测试项或测试小项。
3. 从当前选中节点解析出要执行的测试小项集合。
4. 读取当前勾选且已经扫码生成电表地址的工位，默认最多 48 个工位。
5. 生成本次运行编号 `currentRunId`。
6. 创建 `CancellationTokenSource`，用于“停止测试”按钮取消任务。
7. 禁用“执行测试”按钮，启用“停止测试”按钮。
8. 按选中的测试小项逐项执行。
9. 每个小项执行结束后，将结果写入界面、缓存、本地数据库和测试日志。
10. 全部结束、异常或取消后，恢复按钮状态。

## 2. 测试小项解析

测试方案来自 `MeterTest/config/MeterTestPlanConfig.xml`。

TreeView 三层结构为：

1. 方案：`Scheme`
2. 测试项：`TestItem`
3. 测试小项：`TestSubItem`

界面调度层会根据当前选中的 TreeView 节点生成 `SelectedSubItemContext`：

- 如果选中方案，则执行该方案下所有启用的小项。
- 如果选中测试项，则执行该测试项下所有启用的小项。
- 如果选中测试小项，则只执行当前小项。
- `enabled="false"` 的小项不会执行。

## 3. 执行模式

每个 `TestSubItem` 通过 `executionMode` 决定实际流程。

当前主要支持以下执行模式：

- `StationTcp`：每个工位都有独立 IP 和端口，测试报文直接发送到对应工位。
- `ControlPcbDailyTiming`：通过控制 PCB 批量控制多个表位执行日计时。
- `ControlPcbStartingError`：读取标准表常数，通过控制 PCB 设置常数并启动 0x38 起动误差试验。
- `SerialPortServerBaudRateSync`：执行通信测试原有的连接、读取、校验和修改波特率步骤。
- `StartingSource`：按资产档案计算启动电流并升源。
- `StartingTimeWait`：按资产档案计算Tst上限，并按多工位最大值统一等待。
- `ControlPcbStartingErrorRead`：通过控制PCB发送0x38结果查询并解析float误差。
- `StartingErrorJudge`：按资产档案和JJG596误差表计算各工位限值，再判断已读取的起动误差。
- `ControlPcbDeviceSelfCheck`：在升源前通过V2控制PCB执行0x86短路、0x84断路和0xCA温度读取。

调度入口是 `ExecuteTestContextAsync()`：

1. 每轮开始时先由 `MeterTestRunPreparationService` 完成一次台体切换和源 Ini 初始化。
2. `MeterTestWorkflowRouter` 将 XML 的执行模式解析为明确流程类型。
3. 窗体只把上下文和工位集合交给对应流程服务，并接收服务结果更新 UI。
4. 通信测试先按 XML 树执行原波特率同步流程，最后地址读取失败时再进入备用波特率回退。

## 4. 源控制流程

点击“执行测试”后，`MeterTestRunPreparationService.ExecuteAsync()` 会先执行一次台体类型切换和
`MeterTestSourceControlService.InitializeRunAsync()`。后续测试小项只调用所需的升源/降源输出，
不会重复发送 0x82 或 Ini；只有物理串口、相制、电压代码、基本电流或有功常数发生变化时才重新 Ini。

源控制配置在 `MeterTest/config/MeterTestStationConfig.xml` 的 `SourceControlConfigs` 节点内。
台体类型切换的多个通信端点配置在 `MeterTest/config/MeterTestStationConfig.xml` 的 `BenchTypeSwitchConfig/Endpoint` 节点内。

支持的源控制接口类型包括：

- `AnyUIOutput`
- `Adj`
- `RangeOutputUI`
- `ShutPowerSource`

执行逻辑：

1. 每次点击“执行测试”创建新的源控制运行批次，并在进入首个测试小项前完成一次前置准备。
2. 不论选择1个还是48个工位，同一公共源批次只初始化一次、每个源参数点只下发一次升源接口；重复入口共享同一个任务结果。
3. 从所有选中工位资产信息读取“电表类型”和“接入方式”。
4. 单相直接式发送模式 `03`，三相直接式发送 `01`，三相互感式发送 `02`；混选不同模式时停止控源。
5. 向 `BenchTypeSwitchConfig` 下全部启用的 `Endpoint` 并行发送 `55 44 ... 02 82 01 模式 ... AA BB`；重复 IP/Port 自动去重。
6. 每个装置通信板可能先上传对表位控制板的广播报文；程序会在各自连接上继续读取，直到收到匹配的第二条 `0x82` 上行应答。
7. 分别校验各端点应答方向、协议类型、命令码、数据项、长度和校验和；应答地址不参与判断。
8. 单相只选择 `supportsSinglePhase=true` 的端点；三相按配置选择全部适用端点。适用端点全部成功后统一等待 `delayAfterSuccessMs`，再执行源 Ini。
9. 根据单相/三相、相别、电压、电流、角度、功率因数等参数组装源控制参数。
10. 调用 `XYCtr` 对应接口升源或降源。
11. 如果前置台体切换或 Ini 初始化失败，本轮方案不会进入具体测试小项；单个升源接口返回失败时，仍按流程读取标准表实际值并以实测结果决定是否继续。

### 4.1 起动试验启动电流升源

方案树中的 `升源（启动电流）` 使用 `executionMode=StartingSource`，仍复用源控制服务。
程序从选中工位资产信息读取接入方式、基本电流和有功等级，计算启动电流 `Ist`：

```text
直接式：Ist = 基本电流 / 10 × 系数
互感式：Ist = 基本电流 / 20 × 系数
```

系数规则：

| 接入方式 | 有功等级 | 系数 |
| --- | --- | --- |
| 直接式 | A | 0.05 |
| 直接式 | B/C/D | 0.04 |
| 互感式 | A | 0.05 |
| 互感式 | B | 0.04 |
| 互感式 | C/D/E | 0.02 |

计算出的 `Ist` 会作为 `Ini_接线方式_电压代码_电流_有功常数_E` 中的电流参数，
随后按现有流程打开串口、初始化电表参数、升源和读取标准表确认源状态。多个选中工位计算出的
`Ist` 必须一致，否则停止升源并输出具体工位的计算结果。

升源指令下发后每 `3s` 读取一次标准表，最多等待 `20s`。单相逐项校验 `Ua/Ia`，三相逐项
校验 `Ua/Ub/Uc` 和 `Ia/Ib/Ic`；所有参与输出的相量都进入目标值正负 `0.03%` 范围后才判定
升源成功。普通通信测试只校验输出电压，起动试验同时校验电压和计算得到的 `Ist`。

### 4.2 开启起动误差试验

方案树中的 `开启起动试验（启动误差）` 使用 `executionMode=ControlPcbStartingError`。

执行顺序：

1. 调用 `XYCtr.CallReadStandConstAsync()` 读取标准表有功脉冲常数。
2. 从资产信息读取每个工位的“有功常数”。
3. 按 `ControlPcbGroups` 将选中工位分配到对应控制 PCB，不同 PCB 组并行执行。
4. 发送 `0xA2 + 8字节标准表常数`，常数按小端格式编码。
5. 仅对 A2 应答正常的工位发送 `0xA0 + 4字节电能表有功常数`。
6. 仅对 A0 应答正常的工位发送 `0x38 + 0x00 + 脉冲数 + 次数 + 脉冲类型`。
7. 默认启动数据项为 `00 02 01 00`，表示开始试验、2个脉冲、1次、有功。
8. 每一步都校验响应帧、方向、协议类型、命令码、表位地址和原命令数据项。
9. 单个工位失败不会中断同组其他工位，最终结论按工位保存到界面和数据库。

对应 XML 参数为 `basicErrorPulseCount`、`basicErrorTestCount`、`basicErrorPulseType` 和
`packetIntervalMs`。当前流程只支持控制 PCB V2 协议。

### 4.3 起动时间等待

方案树中的 `等待起动时间` 使用 `executionMode=StartingTimeWait`。计算公式为：

```text
Tst上限 = (1 + Est / 100) × 3.6×10^6 / (C × Pst × Ki × Ku)
Pst = U × Ist × d
```

- `Est`：A级2.5%、B级1.5%、C级1.0%、D级0.4%。
- `C`：资产信息中的有功常数，单位 `imp/kWh`。
- `U`：资产信息中的额定相电压，例如 `3×220/380V` 取 `220V`。
- `Ist`：与升源步骤共用 `MeterTestStartingTestCalculator` 计算结果。
- `d`：单相1、三相三线2、三相四线3；旧资产值“三相”兼容按三相四线处理。
- `Ki/Ku`：当前固定为1。

程序逐工位记录完整计算参数；多工位同时试验时，先把最大的单脉冲 `Tst上限` 向上取整，
再乘以 `startingTimeMultiplier` 和“开启起动试验”配置的 `basicErrorPulseCount` 统一等待。
当前默认倍率为 `2`、脉冲数为 `2`，因此实际等待是单脉冲Tst的4倍。例如原等待时间为
`ceil(Tst上限)×2=336s` 时，最终等待时间为 `336×脉冲数2=672s`。
日计时和起动试验复用 `DelayTestWithCountdownAsync()`，只打印开始和结束，不逐秒输出日志。

### 4.4 读取并判断起动误差

`读取误差结果` 节点使用 `executionMode=ControlPcbStartingErrorRead`，默认下发：

```text
55 44 0A 00 00 01 02 38 AA 01 01 F1 AA BB
```

程序校验V2帧、方向、协议类型、命令码、表位地址和 `AA 01 01` 结果头，再按4字节小端
`float` 解析误差。多工位结果按工位号分别缓存，单个工位无应答不会影响其他工位读取。

`判断误差结果` 节点使用 `executionMode=StartingErrorJudge`。程序按工位读取接入方式、有功等级、
电流规格和基本电流，计算 `Ist/Imin` 对应的规程最大允许误差，再乘以 `60%` 得到实际判定区间：

```text
下限 = -最大允许误差 × 60%
上限 = +最大允许误差 × 60%
下限 <= 实测误差 <= 上限：合格
```

工位日志和结构化结果同时保存实测误差、规程最大允许误差上下限、60%判定上下限和不合格原因。
协议特殊值`1.0`（无完整脉冲）、`2.0`（尚未计算完成）及没有读取到有效结果的工位直接判定不合格。

### 4.5 潜动试验电压升源

`升源（潜动电压）` 节点使用 `executionMode=CreepingSource`。程序从资产信息读取额定相电压，
按下式计算实际输出电压：

```text
Ucreep = 1.1 × Un
```

例如额定电压为 `220V` 时，实际升源目标为 `242V`。初始化电表参数仍使用额定电压 `220V`
对应的电压档位，不能把 `242V` 传给 `Init_meterV`。

`AnyUIOutput` 参数示例：

```text
单相：242_0_0_0_0_0_0_0_0_120_240
三相：242_242_242_0_0_0_0_0_0_120_240
```

潜动升源不输出电流。升源后每3秒读取一次标准表，最多等待20秒；单相校验 `Ua`，三相校验
`Ua/Ub/Uc`，全部进入 `242V` 正负 `0.03%` 范围后判定该步骤合格。

升源稳定后的潜动流程使用控制PCB V2协议：

1. 按工位发送 `0x25+01` 启动，启动应答数据项必须严格为单字节 `01`。
2. 按方案 `creepingTimeSeconds` 手动配置值等待；该时间不进入 `0x25` 报文。
3. 按工位发送 `0x25+AA` 获取结果。
4. 结果上行数据项为 `AA + 4字节小端uint`，该uint是实际收到的脉冲数。
5. 实际脉冲数小于等于1判定合格；无应答或结果解析失败判定不合格。

表位地址 `01` 的启动报文为：

```text
下行：55 44 08 00 00 01 02 25 01 31 AA BB
上行：55 44 08 00 01 01 02 25 01 32 AA BB
```

### 4.6 正向/反向有功基本误差

`基本误差-正向有功` 和 `基本误差-反向有功` 各包含18个测试点。方案树只展示测试点，
每个 `executionMode=BasicErrorPoint` 小项内部由 `MeterTestBasicErrorService` 统一执行：

1. 根据资产信息和测试点计算额定电压、基本电流、`Imin/Itr/Imax`、测试电流、功率因数和正反向参数。
2. 调用现有源控服务复用已打开的源串口和成功的电表初始化；`Ini` 使用资产基本电流 `Ib/In`，参数未变化时不重复初始化。
3. 基本误差固定调用 `AnyUIOutput`，直接下发测试点的绝对电压、电流和功率因数相角，避免大电流点换算成 `Adj` 百分比后超出接口范围。单相输出 A 相；三相 `H` 输出三相电流，`A/B/C` 只输出对应相电流。
4. `AnyUIOutput` 下发后使用标准表的实际电压、电流值做正负0.03%稳定性校验；接口返回失败时仍执行20秒实测复核。
5. 读取标准表脉冲常数，按工位依次发送A2、A0和`38 00`，每一步收到正确应答后才继续。
6. 按 `T=3.6×10^6×N/(C×P)` 计算单次理论时间；`basicErrorPulseCount=0` 时自动提高N，保证单次测量时间不少于10秒。总等待时间为 `ceil(单次理论时间)×试验次数+20秒`；脉冲数N已包含在单次理论时间中，不再作为外层倍率。
7. 第一轮等待后发送`38 AA`执行“第一次读取误差结果”。若只返回 `1/2` 或包含状态值`2.0`，只将该工位放入待完成集合；再等待一轮后发送相同的`38 AA`，执行“第二次读取误差结果”。已返回全部结果的工位不重复读取。
8. 补等轮数按首次缺失或未完成的结果数限制，超过上限仍不完整、最终结果值为`1.0`或无应答时判为不合格。
9. 结果数量达到配置试验次数后，先求所有误差结果的平均值。`MeterTestErrorResultComparer`按能量类型、接入方式、等级、功率因数和当前电流所属区间计算规程最大允许误差；旧版`basicErrorLimit/basicErrorLimits`只保留XML反序列化兼容，不参与当前判定。
10. 实际误差限统一为`规程最大允许误差×60%`，判定条件为`平均误差 >= 下限 && 平均误差 <= 上限`。日志、数据库结果和Excel明细同时输出每次误差、平均值、规程最大允许区间、60%判定区间和不合格原因。

误差算法集中在`MeterTestErrorResultComparer.cs`，同时封装有功A-E级和无功直接式/互感式
3、2、1S/1、0.5S级的规程表。“不测试”的等级/电流/功率因数组合会返回不适用，不能被误判为合格。

资产电流支持两种格式：完整规格如`0.25-0.5(60)A`会直接取得Imin/Itr/Imax；只有`5A`
这类基本/额定电流时，程序按接入方式推导。直接式按`Itr=Ib/10、Imax=12Ib`，A级
`Imin=0.5Itr`、B/C/D级`Imin=0.4Itr`；互感式按`Itr=In/20、Imax=4In、Imin=0.2Itr`。
多工位计算出的相制、电压、基本电流或测试电流不一致时停止当前测试点，避免公共源输出冲突参数。
一个基本误差测试点还会建立完整流程批次缓存：即使上层意外按工位重复进入，初始化、升源、
A2/A0/0x38启动、等待和结果读取也只执行一套，所有工位共享该批次并分别保存应答和结论。

### 4.7 国网智芯蓝牙接口检测

`BluetoothStationTcp` 是蓝牙转换器专用执行模式。每个选中工位都从方案XML的
`BluetoothTcpChannels/BluetoothTcpChannel` 读取独立 `IP/Port`。流程首先通过同 IP 的
`64444` 管理端使用通用串口服务器协议将该通道设为 `9600-8-E-1`，再建立蓝牙工位 TCP 连接。
资产信息中的 `IP/Port` 只用于485通信，蓝牙流程不会回退使用；同时也不使用普通
`StationTcp`、控制PCB长连接或全局TCP连接池。多工位通过 `Task.WhenAll` 并发执行，
单个工位失败不中断其它工位。

蓝牙通道按工位号唯一映射，例如：

```xml
<BluetoothTcpChannel station="1" enabled="true" ip="192.168.127.131" port="5001" />
```

默认配置会生成1-48工位的禁用占位项。现场必须填写蓝牙转换器端点并启用；缺失、重复、
禁用或端点非法时只判对应工位失败，不会误连该工位的485端口。

方案树固定五个小项：

1. `修改串口波特率 9600-8-E-1`：连接同IP的 `64444` 管理端，先解锁，再按 `BluetoothTcpChannel` 端口发送通用设置报文，设置立即生效。
2. `复位蓝牙`：新建工位TCP连接，发送 `0x00`，校验 `0x80 + 00`应答。
3. `连接电表`：从资产信息读取12位电表地址，按6字节BCD逆序后发送 `0x01`自动连接命令，校验 `0x81 + 00`应答。
4. `检定预处理`：发送 `0x07`；启动成功后每2秒发送 `0x08`。状态 `00`为成功，`01`为失败，`02`继续轮询，整体最长等待40秒。
5. `读取通信地址40010200`：复用本轮已经建立的工位蓝牙TCP连接，通过 `SGCCTools.BuildMeterAddressReadRequest()` 发送698定址读取报文；复用 `ParseBroadcastAddressResponse()` 校验并解析 `OAD=40010200`。该步骤不发送 `F1010200` 安全模式读取。

同一轮测试中，每个蓝牙专用 `IP:Port` 只建立一次TCP连接，复位、连接电表、检定预处理、
读取地址四步依次复用。同一 IP 的 `64444` 管理连接也只建立一次，后续通信测试直接复用。首次连接失败会缓存到本轮结束，后续步骤不再重复连接该端点。

最后一步会校验698起止符、长度、HCS、FCS、`8501`、`40010200`、数据类型 `09`及6字节地址，并将返回地址与资产电表地址比较。每个小项的TCP建连、发送HEX、接收HEX、帧校验和结论都写入当前工位日志。

### 4.8 设备自检测试

`设备自检测试` 固定排列在 `通信测试` 之前，三个小项都使用程序启动时建立的
`ControlPcbGroups` V2长连接，不会在测试中重复连接控制PCB。每个控制组并发执行，组内工位按
`packetIntervalMs` 间隔发送；一个工位无应答只停止该工位当前步骤，不中断其他工位。

1. `检测单元短路检测`：发送 `86 01` 启动，等待 `selfCheckDelayMs` 后发送 `86 AA` 读取结果。结果码`00`合格，其他结果码按A/B/C相短路位置判不合格。
2. `检测单元断路检测`：发送 `84 01` 启动，等待后发送 `84 AA`。结果码`01`表示有电表且电流线路正常；`00/02`判不合格。
3. `检测单元温湿度检测`：当前协议只给出了温度命令，发送 `CA + temperatureSensorIndex + AA`，解析4字节有符号小端温度值。由于协议未定义缩放比例，日志明确记录“温度原始值”，不擅自换算单位。

短路检测有独立安全前置流程：

1. 检查源控制服务是否已经执行过升源，并检查最近标准表 `Ua/Ub/Uc`。
2. 任一相高于 `selfCheckMaximumSafeVoltage`，或程序记录源仍处于输出状态时，调用 `ShutPowerSource(0)` 同时降电压和电流。
3. 最长20秒读取标准表，直到 `Ua/Ub/Uc` 全部不高于安全阈值。降源失败、无法复核或超时均禁止发送0x86。
4. 电压安全后显示红色警告弹窗；只有用户点击“确认执行”才发送短路检测报文，取消时不发送任何报文。

设备自检的所有子步骤统一写入 `设备自检测试工位N.log`。

### 4.9 手动降源

测试过程区域的“降源”按钮从 `SourceControlConfigs/SourceControlConfig.protocol`
选择源厂家驱动。当前只支持 `protocol="XYCtr"`，调用
`XYCtr.CallShutPowerSource(0)`，同时停止电压和电流输出。

单相、三相参数可以是同一台源的不同配置，但所有启用的源配置必须使用同一个
`protocol`。若缺失配置、出现多个厂家协议或驱动未实现，按钮会报错且不调用DLL。
测试运行期间点击降源会先取消当前测试，防止后续测试节点再次升源。

### 4.10 工位电源全量同步

测试方案区域的工位勾选联动保持不变：选中工位根据资产中的单相/三相类型上电压并通电流，
取消选中时断电流并下电压。点击“全选/清空”或正式开始测试前，程序还会遍历所有
`enabled="true"` 的 `ControlPcbGroup` 做一次全量同步。本轮选中工位执行上电，其余映射工位明确执行下电。
表位地址按 `meterAddressStart + stationNo - stationStart` 计算。未选中工位优先按资产类型关闭对应相；
若资产类型缺失或无法识别，则使用ABC三相关闭命令作为安全兜底。

## 5. StationTcp 流程

`StationTcp` 用于工位独立通信，例如通信测试里的“地址读取”。

执行入口是 `ExecuteStationSubItemAsync()`。

核心流程：

1. 获取当前勾选的工位列表。
2. 每个工位创建一个独立任务。
3. 使用 `Task.WhenAll()` 并发执行所有选中工位。
4. 普通工位请求调用 `SendStationRequestAsync()`；698地址读取调用 `MeterTestCommunicationAddressService`。
5. 工位连接成功后生成并发送请求报文。698 地址读取会把请求模板中的 6 字节地址替换为当前工位“电表地址”列的地址，并重新计算 HCS/FCS；其他测试直接发送配置中的 requestHex。
6. 在 `timeoutMs` 内等待响应。
7. 按 `responseParser` 判断响应是否合格。
8. 将结论写入界面、数据库和日志。

### 5.1 通信测试中的波特率同步与回退

通信测试方案树保留原来的五个小项：

1. 串口服务器连接
2. 读取串口参数
3. 校验工位波特率
4. 修改不一致波特率
5. 地址读取

前四步继续走原 `MeterTestSerialPortServerService` 流程：按IP连接管理端 `64444`，发送电表V2
`F3` 读取端口参数，与资产信息比较，仅对不一致端口发送 `F1` 修改；设置立即生效且不重启。

第五步先按原流程已经同步好的资产波特率连接工位 `IP:Port` 并发送698定址读取报文：

1. 如果解析出合法地址，立即停止当前工位流程，并比较返回地址和资产地址。
2. 如果没有解析出地址，从SQLite `MeterTestAssetOption` 表按顺序读取全部 `BaudRate` 候选项。
3. 排除已经尝试的资产波特率后，使用 `GenericSerialPortServerProtocol.BuildCommandSet()` 发送 `FF 02` 解锁和 `FF 0B` 设置命令。
4. 每次设置候选波特率后重新读取地址；任一候选读取成功即停止，全部候选失败才判定不合格。
5. 多工位地址读取继续并发；同一IP的64444追加设置操作由服务内部串行化并复用一条管理连接。
6. 同一IP的64444首次连接失败后缓存本轮失败，其余工位不再重复连接；设置成功后再新建工位 `IP:Port` 连接读取地址。

默认资产波特率为 `9600-8-E-1` 时，后续依次尝试 `1200-8-E-1`、`2400-8-E-1`、
`4800-8-E-1`、`115200-8-E-1`。如果资产保存的是其他波特率，该值仍固定排第一，数据库其余候选各尝试一次。

### 5.2 地址读取解析

通信测试中的地址读取使用 `Sgcc698BroadcastAddress` 解析器。

该解析器会校验：

1. 698 报文起始符 `68` 和结束符 `16`。
2. 长度域是否和实际报文长度一致。
3. 帧头校验 HCS。
4. APDU 是否为读取响应，例如 `85 01`。
5. OAD 是否为配置值，例如 `40 01 02 00`。
6. 数据类型是否为 `09`。
7. 数据长度是否为配置值，例如 `6`。
8. 帧尾校验 FCS。

解析成功后，会把数据区内的 6 字节电表地址写入“表位地址”列。

## 6. ControlPcbDailyTiming 流程

`ControlPcbDailyTiming` 用于日计时，参考 `ElectricEnergyMeterControlV1/V2` 的控制 PCB 协议。

执行入口是 `ExecuteControlPcbDailyTimingStepAsync()`，方案树中的日计时小项按三轮展示：

```text
开始日计时实验-第1次 -> 延迟等待110秒倒计时-第1次 -> 读取日计时结果-第1次
开始日计时实验-第2次 -> 延迟等待110秒倒计时-第2次 -> 读取日计时结果-第2次
开始日计时实验-第3次 -> 延迟等待110秒倒计时-第3次 -> 读取日计时结果-第3次
```

点击“日计时”测试项时，完整流程只执行一次，后续树节点用于展示已经完成的流程阶段，不会重复发送整套报文。

核心流程：

1. 根据配置找到启用的控制 PCB 组。
2. 根据当前勾选的工位匹配对应 PCB。
3. 每个 PCB 组创建一个独立任务并发执行。
4. 每个 PCB 组只负责自己配置范围内的工位。
5. 建立 TCP 连接到控制 PCB 的 IP 和端口。
6. 按工位对应的表位地址分别发送“开始日计时”报文。
7. 每条报文发送间隔使用 `packetIntervalMs`，默认 100ms。
8. 收集每个表位的开始应答，失败工位不阻断其他工位和后续轮次。
9. 对开始成功的表位执行逐秒倒计时等待。
10. 等待结束后，对成功表位分别发送“日计时结果获取”报文。
11. 解析 `AA + 时间 + 次数` 后的连续 4 字节小端 `float` 误差值。
12. 每轮先计算该工位本轮所有结果值的平均误差，再累计三轮结果。
13. 三轮均获得有效结果且最终平均误差绝对值小于 `0.5` 时判定合格，否则判定不合格。

等待时间计算：

```text
等待秒数 = ceil(dailyTimingTime * dailyTimingCount * 1.1)
```

例如 `dailyTimingTime=60`、`dailyTimingCount=1` 时等待 `66s`。日志只输出一次
“开始倒计时66s”和一次“倒计时结束”，等待期间不再每秒追加日志。

例如时间 10 秒、次数 10 次，则等待：

```text
10 * 10 + 10 = 110 秒
```

## 7. 控制 PCB 映射

控制 PCB 配置在 `MeterTest/config/MeterTestStationConfig.xml` 的 `ControlPcbGroups` 节点内。

典型配置含义：

- `ip`：控制 PCB IP。
- `port`：控制 PCB 端口。
- `protocolVersion`：协议版本，支持 V1/V2。
- `stationStart`：起始工位。
- `stationEnd`：结束工位。
- `meterAddressStart`：起始工位对应的 PCB 表位地址。

例如：

```text
192.168.127.101:4001 控制工位 1-3
192.168.127.101:4002 控制工位 4-6
```

如果工位 4 对应表位地址 1，则工位 5 对应表位地址 2，工位 6 对应表位地址 3。

## 8. 界面结果刷新

测试过程区域有两种视图：

- 测试方案视图：显示选择、工位、测试内容、表位地址、结果、时间。
- 资产信息视图：显示工位、条形码、电表地址、IP、Port、电表类型、接入方式、额定电压、基本电流、电流规格、有功/无功等级和常数、波特率。

点击“测试方案”：

1. 隐藏资产信息列。
2. 显示测试执行相关列。
3. 根据当前选中的测试小项恢复已保存的工位结果。

点击“资产信息”：

1. 显示资产信息列。
2. 允许修改工位 IP、端口和电表档案参数。
3. 显示“保存”和“批量修改”按钮。

条形码支持两套互斥规则：

- 规则1：按用户配置的0基起止位置截取，结束位置包含在结果内。
- 规则2：取条形码索引6开始的2位，再拼接索引10开始的10位，共12位电表地址。

通信测试读取到的响应地址只用于与资产地址比较并形成结论。方案区域仅显示资产档案地址，
不会把响应地址反向写入 `MeterTestMeterArchive`。

电流规格下拉框根据接入方式切换：直接式使用 `0.25-0.5(60)A`、`0.25-0.5(100)A`、`0.2-0.5(60)A`、`0.2-0.5(100)A`、`0.5-1(60)A`、`0.5-1(100)A`；
互感式使用 `0.015-0.075(6)A`、`0.003-0.015(6)A`。格式固定为
`Imin-Itr(Imax)A`，基本误差测试点直接从该规格取得Imin/Itr/Imax。

执行测试时界面保持在测试方案视图，不自动切换到资产信息视图。

## 9. 数据保存

MeterTest 使用 SQLite 本地文件数据库，不依赖 Access、ACE、Jet。

数据库路径：

```text
MeterTest/data/MeterTest.db
```

主要保存内容：

- 工位测试结果。
- 工位 IP 和端口配置。
- 控制 PCB 配置。
- 电表资产档案。
- 测试任务、任务工位资产快照、测试小项结论和结构化测量值。

结果保存后，用户切换测试项或重启程序时，可以恢复对应测试内容的结论和表位地址。

点击“执行测试”完成方案后会自动保存任务；点击测试过程区域的“数据保存”可手动保存。
同一次运行的自动保存和手动保存使用同一个RunId，手动保存会覆盖任务快照，不会重复生成任务。
部分项目未测试时保存为“未完成”，已出现任一失败时工位总结论为“不合格”。

点击操作区“测试结果”切换到内嵌结果视图：顶部固定高度表格选择任务，左下选择工位电表对象，
右下查看该工位全部测试明细。明细同时保存日计时3轮误差与平均误差、起动误差、潜动脉冲数、
基本误差每次结果与平均值；起动和基本误差明细还展示规程最大允许区间与60%判定区间。

结果窗口“数据导出”使用 `MeterTest/templates/MeterTestResultTemplate.xlsx`。现场可修改模板标题、
标签、字体、颜色、列宽和第2行数据样式，但必须保留三个工作表名称、任务信息B2:B9位置、
工位汇总和测试明细的第1行表头及第2行模板样式。变量说明见 `MeterTest/templates/README.md`。

## 10. 测试日志

工位通信日志保存到：

```text
XCKJ_logs/TextLog/yy/MM/dd
```

文件命名规则：

```text
测试项名称 + 工位号.log
```

示例：

```text
通信测试工位1.log
日计时工位1.log
蓝牙接口检测工位1.log
设备自检测试工位1.log
基本误差-正向有功工位1.log
```

日志文件只按父级 `TestItem + 工位` 建立。该测试项下所有 `TestSubItem`，以及基本误差、

正常通信日志包括：

- 准备连接。
- 连接成功。
- 发送报文。
- 接收报文。
- 测试结论。

连接失败或无响应时，也会按相同分隔格式写入日志，方便现场排查。

## 11. 新增测试项方法

新增测试项优先修改 `MeterTest/config/MeterTestPlanConfig.xml`。

### 11.1 新增普通工位 TCP 测试

配置要点：

- `executionMode="StationTcp"`
- `requestHex` 填写下发报文。
- `timeoutMs` 填写等待时间。
- `responseParser` 选择 `HexMatch` 或 `Sgcc698BroadcastAddress`。
- `matchMode` 可选 `Exact`、`Contains`、`StartsWith`。

### 11.2 新增控制 PCB 日计时测试

配置要点：

- `executionMode="ControlPcbDailyTiming"`
- `dailyTimingTime` 填写单次日计时时间。
- `dailyTimingCount` 填写次数。
- `packetIntervalMs` 填写报文发送间隔。
- `controlPcbGroup` 可指定固定 PCB 组；为空时按工位自动匹配启用的 PCB 组。

### 11.3 新增需要升源的测试

配置要点：

- 在 `MeterTestStationConfig.xml` 的 `SourceControlConfigs` 中定义源控制参数。
- 在 `TestSubItem.sourceControlConfig` 中引用源控制名称。
- 测试执行前会先升源，升源失败则不会继续执行该测试小项。

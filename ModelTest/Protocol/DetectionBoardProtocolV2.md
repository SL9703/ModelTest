# 检测装置电测板卡通信协议 V2.0

## 协议组成

台体通信协议包括控制协议和透传协议。

控制协议用于控制台体模块的电源系统、遥信状态设置、遥控状态读取、电压电流等参数检测。

透传协议用于透传模块和终端、模块与虚拟表之间的通信报文或抄表报文，例如 645、698、376.2、376.3 等。

## 通信参数

控制协议采用 RS485 通信：

- 波特率：115200 B/S
- 校验：无校验
- 停止位：1 位

透传协议通信端口参数根据被测模块不同而不同。

## 报文格式

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 起始字符 | 2 字节 | 固定 `55 44` |
| 数据长度 | 2 字节 | 小端格式，表示从“数据长度”到“校验和”的长度，不包含起始字符和结束字符 |
| 数据方向 | 1 字节 | 下行到 MCU 为 `00`，上行到 PC 为 `01` |
| 地址/通道 | 1 字节 | 印制板地址，有效范围 `01`~`FE`，`FF` 为广播地址；装置通信板命令 `80`~`83` 使用 `00` |
| 协议类型 | 1 字节 | bit0 表示控制/透传，bit1~bit7 表示设备类型 |
| 命令码 | 1 字节 | 控制协议表示命令，透传协议表示软件透传通道 |
| 数据项 | N 字节 | 控制协议为命令附加数据，透传协议为透传数据 |
| 校验和 | 1 字节 | 从“数据长度”到“校验和前一个字节”的累加和低字节 |
| 结束字符 | 2 字节 | 固定 `AA BB` |

## 协议类型

协议类型字段按 bit 解释：

- bit0：`0` 表示控制协议，`1` 表示透传协议
- bit1~bit7：设备类型

设备类型：

| 值   | 设备  |
| --- | --- |
| 1   | 电表  |
| 2   | 终端  |
| 3   | 源   |
| 4   | 仓储  |
| 其他  | 预留  |

协议类型组装公式：

```text
协议类型 = (设备类型 << 1) | 是否透传
```

例如终端控制协议：设备类型 `2`，控制协议 `0`，协议类型为 `04`。

例如终端透传协议：设备类型 `2`，透传协议 `1`，协议类型为 `05`。

## 长度说明

数据长度为 2 字节小端格式。

长度范围从“数据长度”字段开始，到“校验和”字段结束，不包含起始字符 `55 44`，也不包含结束字符 `AA BB`。

最小无数据项报文的数据长度为：

```text
数据长度2 + 数据方向1 + 地址1 + 协议类型1 + 命令码1 + 校验和1 = 7
```

## 校验和

校验和为各字节累加和的低字节。

校验范围：

```text
数据长度字段低字节
数据长度字段高字节
数据方向
地址
协议类型
命令码
数据项
```

不包含起始字符、校验和自身、结束字符。

## 应答报文

设置命令：

- 成功：返回码按原命令返回
- 失败：按错误码返回

读取状态命令：

- 成功：返回码按规定格式返回
- 失败：按错误码返回

### 读取模组直流电压/电流/功耗命令 0x07

命令码：`07`

发送数据项：4 字节

| 字节 | 说明 |
| --- | --- |
| 字节1 | 模组类型，`01` 表示真实模组，`02` 表示 sta 模组 |
| 字节2 | 模块号，`01`~`05` 分别表示模块 1~5 |
| 字节3 | 读取项，`01` 电压(mV)、`02` 电流(mA)、`03` 电压电流(mV/mA)、`04` 功耗(mW) |
| 字节4 | 控制字节，`00` 停止连续读取，`01` 启动连续读取，`02` 单次读取 |

接收数据项：

| 字节 | 说明 |
| --- | --- |
| 字节1 | 模组类型，`01` 表示真实模组，`02` 表示 sta 模组 |
| 字节2 | 模块号，`01`~`05` 分别表示模块 1~5 |
| 字节3 | 读取项，定义同发送数据项字节3 |
| 字节4~N | 上传数据，u16 小端 |

说明：

- 读取项为 `03` 电压电流时，每组数据 4 字节：电压 u16 小端 + 电流 u16 小端。
- 读取项为其他值时，每组数据 2 字节。
- 当前控件在 group 内展示原始 HEX 和按 u16 小端解析后的 mV/mA/mW 数据。
- 原协议文字同时出现“发送数据项4字节”和“每秒钟上传数据个数10-1000”，当前实现按 4 字节命令发送，频率输入暂不参与组帧。

下行发送示例，真实模组、模块 `1`、单次读取电压：

```text
55 44 0B 00 00 01 04 07 01 01 01 02 1C AA BB
```

### 三相直接式、互感式和单相选择 0x82

目标：装置通信板，通信地址固定使用 `00`。

发送数据项：2 字节。

| 字节 | 值 | 说明 |
| --- | --- | --- |
| 数据项1 | `01` | PC 控制，装置通信板停止检测直接式/互感式旋钮 |
| 数据项1 | `02` | 由装置通信板发出 |
| 数据项1 | `FF` | PC 恢复装置通信板的旋钮检测 |
| 数据项1 | `AA` | 获取旋钮当前状态 |
| 数据项2 | `01` | 三相直接式 |
| 数据项2 | `02` | 三相互感式 |
| 数据项2 | `03` | 单相 |

当前代码在 `01-PC控制` 时发送所选模式；在 `FF-恢复检测` 或 `AA-读取状态` 时，
数据项2发送 `00` 占位。

PC 下发接线模式切换后，装置通信板会上传两条报文：

1. 装置通信板向表位控制板发送的广播报文。
2. 装置通信板对 PC 下发报文的正式响应。

MeterTest 会记录并跳过第一条广播，只以第二条方向为上行、协议类型为 `02`、命令为 `82`
且模式匹配的应答作为切换成功依据。

## 代码封装

项目中协议封装类：

```text
ModelTest/Protocol/DetectionBoardProtocolV2.cs
```

该类负责：

- 控制协议帧拼装
- 透传协议帧拼装
- 完整帧解析
- 起始符、结束符、长度、校验和校验
- 表位十进制转 16 进制
- 装置通信板 `0x80`~`0x83` 报文组装和 `0x82` 应答校验

`TerminalV2UserControl`、`ElectricEnergyMeterControlV2` 和 `MeterTest` 复用同一协议类，不再各自拼装装置通信板报文。
